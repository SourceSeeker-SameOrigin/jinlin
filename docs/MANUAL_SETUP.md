# 近邻帮 · 只能由人来做的配置步骤

Codex 写代码，但下面这些步骤需要登录微信公众平台、微信开发者工具、微信支付商户平台，只能由你操作。按顺序做。

## A. 主体与小程序账号（第 1–2 周）

1. 办营业执照（个体工商户即可），经营范围包含：跑腿服务、家政服务、日用百货零售、信息咨询服务。
2. 在微信公众平台注册小程序，主体选"企业"（个体户也走这里），名称先填"近邻帮"，被占用就换备选名。
3. 完成微信认证（300 元/年）。未认证不能用微信支付和手机号快速验证。
4. 设置服务类目：**生活服务 > 跑腿**（无需额外资质）。以后加上门保洁再加 **生活服务 > 家政服务**。不要选快递物流类。
5. 小程序备案：公众平台"设置 → 基本设置 → 备案"，按提示填写、短信核验，等管局审核（各地 1–20 个工作日）。**备案通过前不能上线，但不影响开发版和体验版测试。**
6. 填写"用户隐私保护指引"：收集手机号（用于联系上门）、使用相机和相册（服务员拍完成照片）、保存图片到相册（管理员保存海报码）。

## B. 开发环境（第 1 周，与 A 并行）

1. 安装微信开发者工具，导入代码仓库，把 `project.config.json` 的 `YOUR_APPID` 换成你的 AppID。
2. 开通云开发，创建环境（个人版即可），记下环境 ID，填到 `miniprogram/config/env.js`。
3. 数据库：按 `database/README.md` 创建集合、导入种子数据、建索引、设置安全规则。
4. 把你自己设为管理员：先用开发版登录一次，然后在云开发控制台 `users` 集合找到自己那条记录，把 `roles` 改为 `["resident","admin"]`；同时把你的 openid 填进 `config.adminOpenids`。
5. 部署云函数：在终端运行 `npm run sync`，然后在开发者工具里对每个云函数右键"上传并部署：云端安装依赖"。`timer` 部署后再右键"上传触发器"。
6. 每个云函数配置环境变量：`ENV_ID`（环境 ID）、`SUB_MCH_ID`（商户号，没有就先留空）、`ALLOW_MOCK_PAY`（开发期 `true`）。

## C. 微信支付（第 2–3 周）

1. 在微信支付商户平台申请商户号（个体户可申请），完成签约。
2. 商户平台"产品中心 → AppID 账号管理"，关联小程序 AppID；回到公众平台确认关联。
3. 开发者工具"云开发控制台 → 设置 → 其他设置 → 微信支付配置"，添加商户号。商户号管理员的微信会收到授权确认，按提示在"服务商助手"里确认授权给"小程序云开发"服务商。
4. 商户平台"产品中心 → 我的授权产品"，确认授权 JSAPI 支付和退款权限。
5. 把云函数环境变量 `SUB_MCH_ID` 填上商户号；`config` 集合 `payMode` 改为 `wechat`；**`ALLOW_MOCK_PAY` 改为 `false`**。
6. 管理员临时把某项服务价格改成 1 分，按 SPEC §17.2 走一遍真实支付和退款，然后改回原价。

常见报错：`sub_mch_id 与 sub_appid 不匹配` → 第 2 步关联没完成；`受理关系不存在` → 第 3、4 步授权没完成。

## D. 订阅消息（第 3 周）

1. 公众平台"功能 → 订阅消息"，按 `docs/TEMPLATES.md` 选 4 个模板，记下模板 ID。
2. 填进 `config.templateIds`。

## E. 体验版与上线

1. 开发者工具"上传"代码 → 公众平台"版本管理"设为体验版 → "成员管理"添加体验成员（你、服务员、几位种子住户）。
2. 体验版内测 1 周，按 SPEC §17 逐条验收。
3. 备案通过后提交审核。审核说明里写清楚：服务内容、服务范围仅限合作小区、测试账号如何体验（可提供一个已绑定门牌的测试小区）。
4. 审核通过后发布。发布前再次确认 `ALLOW_MOCK_PAY=false`、`payMode=wechat`。

## F. 扩展功能开关：打开前要准备的

代码已全部写好，下表每一项准备好后，在管理后台"功能开关"页打开对应开关。**添加新类目时，以公众平台添加类目页面显示的资质要求为准**；论坛、聊天、二手交易这类用户互相发布内容或互相交易的功能，审核通常比跑腿类目严格，提审前先确认类目能否加上。

**重要：需要新类目的功能，要走一次新版本审核再打开**。先在公众平台加好类目，打开对应开关，再提交新版本审核并在审核说明里写明新功能。不要在审核通过后才用开关打开从未经过审核的功能，这可能被认定为规避审核，导致小程序被处罚或下架。只需要运营准备、不涉及新类目的开关（如优惠券、空置房巡检）可以随时打开。

| 开关 | 打开前要准备的 |
| --- | --- |
| `coupons`、`notices`、`federation`、`stationDelivery`、`vacantHome` | 无额外资质。驿站送上门需先与驿站签合作协议；空置房巡检需在服务协议中写明钥匙保管责任 |
| `board`、`idle`、`events`、`chat` | 公众平台添加与发帖、评论、聊天相匹配的类目（如社交类）；在公众平台配置内容安全的消息推送到 `mediaCallback`；指定专人每天处理举报 |
| `idleEscrow` | 平台代收用户之间的货款，属于电商平台性质，需要对应类目和资质（通常涉及增值电信业务经营许可）；拿到前保持关闭，只用信息模式 |
| `travelCarry` | 依赖 `board`；服务协议写入境外帮带规则 |
| `location` | 公众平台"开发管理 → 接口设置"申请 `getLocation`、`chooseLocation`，写清用途；更新用户隐私保护指引；给每个小区设好坐标 |
| `autoPayout` | 商户平台开通"商家转账"、配置转账场景、充值转账余额；云函数 `payout` 配好 `MCH_ID`、`MCH_SERIAL_NO`、`MCH_PRIVATE_KEY`、`APIV3_KEY`、`TRANSFER_SCENE_ID` |
| `elder` | 陪诊服务员参加陪诊培训并取得证书，管理员核验后勾选证书；与合作食堂签约；必要时添加医疗健康相关类目 |
| `pet` | 服务员宠物照护培训；云函数配好 `SECRET_KEY`（32 字节随机密钥）；服务协议写明钥匙与密码的保管责任 |
| `recycle`、`points` | 与已备案的正规回收企业签约，回收企业作为商家入驻 |
| `merchants` | 商家入驻协议（佣金、责任、执照公示）；开锁类商家需公安部门备案（按当地要求） |
| `ads` | 广告审核制度；广告位价格表；广告内容符合广告法 |
